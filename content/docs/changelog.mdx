## Unreleased

We've been auditing the registry component by component, starting with `badge-type` and `pokemon-card`. The goal: every component should work out of the box after a CLI install, with no tribal knowledge required. Along the way the docs got a full table-of-contents rebuild, richer examples, and the landing page grew from a lone hero into a complete site.

### Pokemon Card — cleaner API

`pokemon-card` used to require magic classes to look right: every single consumer repeated `className="overflow-hidden p-2"` to get the tinted frame. That knowledge now lives in the component. Drop the classes; the frame is the default.

```tsx
// Before
<PokemonCard className="overflow-hidden p-2" type="electric">

// After
<PokemonCard type="electric">
```

The rest of the cleanup:

- **Breaking:** the `isMega` prop is now `mega`, matching shadcn naming conventions (`asChild`, not `isAsChild`).
- The header slot had conflicting leftover classes (`border px-2 py-1` silently overriding `px-4`). It's now a single coherent declaration with a proper `size="sm"` variant.
- `PokemonCardOverlay` pins flush to the corners (`top-2/left-2` instead of `top-4/left-4`), so dex numbers and type badges sit tight against the media edges.
- `PokemonCardFooter` is styled as a white band like the header, and `PokemonCardContent` paddings scale with the frame.

### Mega rainbow ships with the CLI

The animated rainbow surface for Mega forms only worked on this site — the CSS lived in our `globals.css`, so CLI installs of `@compodex/pokemon-card` got a dead class and a static card. The keyframes and class now travel in the registry item's `css` field and install automatically:

<CommandBlock command="shadcn@latest add @compodex/pokemon-card" />

### Badge colors survive portals

The `soft` variant of `badge-type` lost its colors inside portaled content like tooltips and dropdowns, because the Tailwind-generated `bg-(--pokemon-type)/40` utilities didn't resolve across the portal boundary. Soft badges now compute their background and text color inline from a per-type map, so they render correctly anywhere in the tree.

### Stat colors are theme tokens

`pokemon-stat` used to hardcode a hex color per stat. Each stat is now backed by a `--color-stat-*` token with tuned light and dark values, so the bars adapt to your theme like every other CompoDex color:

```css
:root {
  --color-stat-hp: #22c55e;
  --color-stat-attack: #f97316;
  /* ...defense, special-attack, special-defense, speed */
}
```

### Richer component docs

Both audited components got the full documentation treatment:

- **Pokemon Badge:** new examples for badge-as-link (`asChild`) and badge-with-tooltip showing type effectiveness data on hover.
- **Pokemon Card:** new examples covering sprite composition — including the no-artwork case, where `PokemonSpriteFallback` keeps the layout intact — badge overlays in every corner, the mega surface, and a `size="sm"` comparison.
- **Complete API references:** props tables for every exported subcomponent (all 10 of Pokemon Card's), driven by a single source of truth in `lib/components-api.ts`.

### Docs table of contents, rebuilt

The table of contents was a 275-line monolith. It's now composed shadcn-style: `TocItem`, `TocList`, and `TocFloating` primitives in `ui/`, scroll-state hooks in `lib/hooks/`, and a thin `DocsTableOfContents` that picks the right variant per viewport. The active section draws a primary indicator bar directly over the aside's dashed border, and the mobile floating variant shows reading progress in a ring.

The aside also grew from 15rem to 18rem and now ends in a library promo card with a 3D-tilted component preview that dissolves into the background.

### The landing page is a full site now

The home page grew five new sections below the hero — Features, How It Works, Core Building, Why This Kit, and FAQ — each separated by dashed rules that run edge-to-edge against the page's side borders.

There's also a site-wide footer: brand info and credits, Docs/Components/Project link columns aligned to the content grid, the Nintendo/Pokémon trademark disclaimer, and an oversized Compodex wordmark clipped by the bottom edge of the page.

### CompoDex joins Kromm Solutions

CompoDex is the first library shipped under [Kromm Solutions](https://github.com/kromm-solutions) — the KS monogram you see across the site. The repository moved to [kromm-solutions/compo-dex](https://github.com/kromm-solutions/compo-dex) (old links redirect), and the site's credits and logo labels now reflect the brand.

### Hero fixes

- Expanded the Pokémon roster in the hero showcase from 6 to 14 species, with per-breakpoint sprite counts (14 on mobile, 7 on `sm`, 9 on `md`, 5 on `lg`, all 14 on `xl`).
- The showcase now scales from 576px on mobile to full width on large screens.
- Fixed CLI command overflow on ultra-small devices (360px).

## June 2026 — v1.0.0

First production release of CompoDex UI. The registry, the documentation site, and the landing page all ship together as a unified `1.0` milestone.

### Registry components

Six installable registry items are available from day one:

- **`pokemon-type-colors`** — CSS custom-property theme that maps all 18 Pokémon types to consistent HSL color tokens. Install this first; the other components consume it.
- **`badge-type`** — Inline type badge rendered with the correct type color, border, and contrast. Supports all 18 types and a `ghost` variant for muted displays.
- **`pokemon-card`** — Full Pokémon card with sprite, name, National Dex number, type badges, and an optional stat bar. Composes `badge-type` and `pokemon-sprite` internally.
- **`pokemon-sprite`** — Sprite renderer backed by PokéAPI CDN. Ships an expanded size scale: `xs`, `sm`, `md` (default), `lg`, `xl`, `2xl`, and a dedicated `card` size tuned for use inside `pokemon-card`.
- **`pokemon-stat`** — Horizontal stat bar for HP / Attack / Defense / Sp. Atk / Sp. Def / Speed. Animated fill on mount, color-coded by stat value.
- **`pokedex`** — Full-page Pokédex shell. Search field, type filter, infinite scroll grid, and a side panel that renders a `pokemon-card` for the selected entry.

### How to add a component

Install the theme tokens first, then add any component:

<CommandBlock command="shadcn@latest add @compodex/pokemon-type-colors" />

Then add the components you need, for example:

<CommandBlock command="shadcn@latest add @compodex/pokemon-card" />

All six items are individually installable:

<CommandBlock command="shadcn@latest add @compodex/badge-type" />

<CommandBlock command="shadcn@latest add @compodex/pokemon-sprite" />

<CommandBlock command="shadcn@latest add @compodex/pokemon-stat" />

<CommandBlock command="shadcn@latest add @compodex/pokedex" />

<Callout type="tip" title="Install order matters">
  Always add `pokemon-type-colors` before any other CompoDex component. The
  type CSS tokens are defined there and all other components depend on them at
  runtime.
</Callout>

### Quick usage example

```tsx
import { PokemonCard } from "@/components/compodex/ui/pokemon-card"

export default function Page() {
  return (
    <PokemonCard
      id={6}
      name="Charizard"
      types={["fire", "flying"]}
      sprite="https://raw.githubusercontent.com/PokeAPI/sprites/master/sprites/pokemon/other/official-artwork/6.png"
    />
  )
}
```
